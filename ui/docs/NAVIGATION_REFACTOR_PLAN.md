## 수정 전 기준값

기존 테스트: Node 환경 20개 통과. `audit-route-quality.py`: 152노드 중 맞이방에서 150개 도달, 2F 2개 단절. 맞이방→마루노바는 64.51m, 4노드, 2회 회전, 4안내. 기존 마루노바 회귀 전 값은 [ROUTE_QUALITY_AUDIT.md](ROUTE_QUALITY_AUDIT.md)에 보존한다.

맞이방→계단·에스컬레이터 `to=49`의 현재 거리 우선 그래프 경로는 `C01 H06 H07 P26 B05 B06 B07 B08 B09 B10 P50`, 약 146.34m다. 원본 Polyline은 `P26→B05→B06`에서 `(520,1145)→(520,1105)→(520,1215)`로 왕복한다. 서쪽 긴 통로의 각 5~15 SVG 단위 지그재그도 안내 각도 임계값을 넘는다. 이 경로와 마루노바를 필수 회귀로 고정한다.

## 구현 순서와 안전 경계

1. 원본 JSON은 보존하고, 현재 계산 그래프에 변경 이력·검증 상태를 추가한다. Edge와 노드 중복·좌표·가중치·교차점·장애물 검사를 강화한다. 검증된 교차점만 noding한다.
2. SVG의 `map-floor` 윤곽과 `room-*`, 제한 구역의 도형으로 층별 공간 데이터를 생성한다. SVG 바닥 윤곽은 현장 보행 가능성의 증명이 아니므로 `ESTIMATED`로 기록한다. 건물 밖·도형 없는 곳은 `UNKNOWN_AREA`로 남긴다.
3. 기존 `route.ts`를 일반/배리어프리와 최단/간단 경로를 지원하도록 확장한다. 방향 상태를 유지하고, 계단·에스컬레이터 제약과 층간 링크 방향을 적용한다. 최단 경로 대비 최대 10% 추가 거리 안에서만 안내 복잡도 개선 후보를 선택한다.
4. 넓은 공간의 자유 이동은 검증된 단일 보행 Polygon 내에서만 Line of Sight와 Visibility Graph를 이용한다. 좁은 통로는 기존 중심선 Edge를 사용한다. 보행 영역이 확인되지 않은 구간에서 사선 지름길을 만들지 않는다.
5. 기존 Polyline을 출입구·층간 Portal을 보존하며 단순화한다. 모든 후보와 최종 선분을 공간 데이터와 대조하고 실패하면 원본 유효 경로로 되돌린다. 거리·시간은 최종 형상으로 다시 산출한다.
6. 안내는 Routing Node와 Geometry Point에서 분리한 Maneuver로 생성한다. 실제 분기·회전·층간 이동·도착만 다음 버튼 단계가 된다. 전체 미리보기와 단계 형상의 결합을 검증한다.
7. 운영 화면과 분리한 개발 전용 검증 페이지 및 JSON 내보내기, 독립적인 공간 경로 비교, 전체 OD 회귀와 CI 검사를 추가한다. 미검증 항목은 PASS로 처리하지 않는다.

## 데이터 근거와 보류 사항

평면도는 SVG ViewBox 직교 좌표를 사용하며 화면 Zoom은 거리 계산에 관여하지 않는다. 계산 JSON의 공통 축척 0.1049m/단위는 실측이 아닌 잠정 추정이다. 층별 축척의 독립 검증이 필요하다. 매장 표시 좌표는 출입구 좌표가 아니다. 기존 `routeNodeId`는 접근 통로 지점으로만 사용하고 출입구 확인이 없는 시설은 추정 상태를 유지한다.

2F의 `2F-E012`는 형상 미검증으로 비활성화되어 있으며 2F 검증 엘리베이터 링크가 없다. 1F 바닥 윤곽 밖의 5개 Edge와 4F 좌표 정합 역시 현장 확인 대상이다. 이 구간을 임의로 활성화하거나 보행 가능으로 확정하지 않는다.
