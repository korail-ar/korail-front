# 브라우저 실내 위치 추정: 기술 참고

이 문서는 [PR #15](https://github.com/korail-ar/korail-front/pull/15)의 기술 검증 내용을 `ui/` 앱에서 참고할 수 있도록 옮겨 정리한 것이다. 원본은 Git 커밋 `f8bfdab`의 `docs/INDOOR_POSITIONING_TECH.md`에서 확인할 수 있다.

## 현재 제품과의 관계

현재 `ui/` 앱은 QR 주소의 `start` 값 또는 사용자가 고른 출발점을 지도에 표시한다. 브라우저 GPS, 걸음·방향 센서, 실시간 통로 매칭, 자동 재탐색은 `ui/`에 구현되어 있지 않다. 아래 흐름은 이전 루트 앱의 `/pdr-test.html`에서 실험한 기술이며, 현재 길안내 화면의 동작을 설명하지 않는다.

## 검증했던 계산 흐름

1. 사용자가 층과 지도상의 출발점을 고른다. 근처 그래프 엣지가 여러 개이면 통로를 자동 확정하지 않고 사용자 확인을 받는다.
2. `DeviceMotionEvent`의 가속도 변화에서 보행 피크를 골라 걸음 수를 센다. 걸음마다 설정한 보폭을 곱해 상대 이동 거리를 추정한다. 당시 기본 보폭은 0.65m였다.
3. `DeviceOrientationEvent`가 절대 방위를 주면 후보 지도 방위로 변환한다. 절대 방위가 없으면 첫 기기 방향을 임시 기준으로 상대 회전만 계산하고 동·서·남·북은 미확정으로 둔다.
4. 이동 거리와 방향을 층별 지도 비율로 바꿔 상대 위치를 갱신한다. 위치 오차는 걸음이 쌓일수록 커지므로 수동 위치 재지정이 필요하다.
5. 추정 위치와 통로 그래프의 거리·연결성·방향을 비교한다. 후보가 겹치거나 불확실성이 크면 경로 진행과 이탈 판단을 보류한다.

```text
가속도 → 걸음 검출 → 걸음 수 × 보폭 ─┐
                                    ├→ 상대 위치 → 지도 표시 → 통로 후보 평가
기기 방향 → 절대 또는 상대 회전 ─────┘
출발점·층 → 그래프와 지도 거리 비율 ──┘
```

## 검증 범위와 이식 조건

- 파란 점은 **확정된 실내 위치가 아니라 출발점에서 누적한 추정 위치**였다. GPS 없이 센서를 사용했으며 자동 층 판별은 없었다.
- 1·3층의 지도 방위 기준과 그래프 거리 비율은 현장 검증 전이었다. 집에서 센서를 움직이는 시험으로 대전역 통로 매칭 정확도를 입증할 수 없다.
- 나침반 방향만으로 경로 이탈을 확정하거나 재탐색하지 않는다. 방향과 위치 불확실성이 낮고 통로 후보가 분리될 때만 진행 판단을 허용해야 한다.
- `ui/`에 이식하려면 기기별 걸음 오차, 현장 실측 거리, 폰 회전에 따른 방향 오탐, 대전역 통로·출입구를 순서대로 검증해야 한다. QR 출발점과 센서 추정 위치는 화면에서도 명확히 구분해야 한다.

원래의 실험 화면·계산 모듈·테스트는 Git 커밋 `f8bfdab`의 `public/pdr-test.js`, `public/location-engine/`, `test/pdr-live.test.js`, `test/pdr-manual-values.test.js`에서 확인할 수 있다. 루트 앱 정리 후에는 현재 코드 경로가 아니다.
