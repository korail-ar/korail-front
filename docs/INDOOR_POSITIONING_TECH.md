# 브라우저 기반 실내 위치 추정 기술 정리

## 목표와 현재 범위

`/pdr-test.html`은 별도 앱이나 건물 장비 없이 스마트폰 브라우저의 동작·방향 센서로 상대 이동을 추정하는 기술 검증 화면이다. 집에서 걷는 거리와 회전이 대전역 예시 평면도 위에 어떻게 표현되는지 시험한다. 집의 실제 벽과 대전역 통로가 일치한다고 가정하지 않는다. GPS는 기본 실험에서 사용하지 않는다.

**현재 표시되는 파란 점은 확정된 실내 위치가 아니라 출발점에서 센서로 누적한 추정 위치다.** 사용자 출발점 지정과 층 선택이 필요하며, 층간 이동은 자동 감지하지 않는다.

## 위치 계산 흐름

1. 사용자가 층과 지도상의 출발점을 선택한다. 출발점은 해당 층 통행 그래프의 가까운 엣지 후보와 매칭한다. 후보가 겹치거나 너무 멀면 사용자가 통로를 확인한다.
2. `DeviceMotionEvent`의 가속도 크기에서 중력·기준값의 변화를 필터링하고 보행 피크의 간격과 반복성을 확인한다. 감지된 걸음마다 보폭을 곱해 상대 이동 거리를 계산한다. 기본 보폭은 0.65m이며 사용자가 조절할 수 있다.
3. `DeviceOrientationEvent`의 방향을 읽는다. 절대 나침반이 있으면 1·3층의 동·서광장 후보 좌표를 이용해 지도 방향으로 변환한다. 이 기준 좌표는 현장 검증 전이므로 지도 정렬도 잠정값이다. 절대 방위가 없으면 첫 기기 방향을 임의 지도 위쪽으로 삼아 상대 회전만 적용하고 **동서남북 미확정**으로 표시한다.
4. 매 걸음의 보폭과 지도 방향을 층별 SVG/m 비율로 변환해 PDR 좌표를 갱신한다. 전체 지도에서 작은 이동이 보이도록 출발점 주변을 확대하고 시작점·현재 점·이동 궤적을 따로 그린다. `지도 좌표 변화`는 출발점 대비 SVG 좌표 차이를 보여 준다.
5. 같은 층의 그래프 엣지와 거리·연결성·방향·이전 위치를 비교해 통로 후보를 평가한다. 후보가 비슷하거나 오차가 크면 통로를 강제로 확정하지 않는다. 예시 지도와 집 구조가 다르므로 집 테스트에서 통로 매칭의 정답을 기대할 수 없다.

```text
가속도 → 보행 피크 → 걸음 수 × 보폭 ─┐
                                     ├→ 상대 좌표 → 지도 표시 → 통로 후보 평가
기기 방향 → 지도 방향 또는 상대 회전 ─┘
출발점·층 → 그래프 및 층별 거리 비율 ────┘
```

위치 업데이트는 3초마다 받는 GPS 값이 아니라 **감지된 걸음마다** 계산한다. 센서가 걸음을 제공하지 않는 동안에는 정지한 것으로 추정할 뿐, 실제 정지를 확인한 것은 아니다.

## 경로와 이탈 판단

목적지를 고르면 기존 그래프와 다익스트라 경로 계산을 재사용해 노란 경로를 표시한다. 지도 방위 기준이 있는 층에서는 경로 구간을 대략적인 동·서·남·북으로 표현한다. 나침반과 경로가 조금 다른 것은 허용하고, 큰 차이가 여러 걸음 지속될 때만 **경로 이탈 의심**을 표시한다. 나침반 방향만으로 이탈을 확정하거나 재탐색하지 않는다.

통로 매칭에 기반한 진행·재탐색은 거리 비율의 실측 보정, 후보의 분리, 낮은 위치·방향 불확실성이 충족될 때만 사용한다. 현재 그래프 거리와 동·서광장 지리 좌표는 현장에서 검증되지 않았다. 집 테스트의 주된 결과는 보행 거리와 상대 회전이며, 대전역에서의 정확한 통로 판단은 별도 검증 대상이다.

## 신뢰도와 알려진 한계

| 조건 | 화면 처리 | 해석 |
| --- | --- | --- |
| 방향 센서 값 없음 | 걸음만 기록, 지도 이동 보류 | 이동 방향을 알 수 없음 |
| 절대 나침반 없음 | 상대 방향으로 점 이동, 동서남북 미확정 | 실제 동·서·남·북 좌표로 해석 불가 |
| 나침반 정확도 낮음 또는 큰 방향 변화 | 불확실성 확대, 방향 판단 보류 또는 경고 | 폰 회전과 몸 회전을 구별하기 어려움 |
| 통로 후보 중복·거리 비율 미검증 | 통로·이탈 확정 보류 | 점의 이동과 실제 통로 일치는 별개 |
| 폰을 흔들거나 주머니에 넣음 | 걸음 오탐·누락 가능 | 센서 패턴만으로 보행을 완벽히 판별 불가 |

가속도와 나침반만으로는 초기 출발 위치를 자동으로 특정하거나, 폰이 향한 방향과 실제 보행 방향을 항상 구별할 수 없다. PDR 오차는 걸음이 쌓일수록 누적되므로 사용자가 지도에서 위치를 다시 지정하는 절차가 필요하다.

## 재현과 현장 검증

1. HTTPS의 `/pdr-test.html`에서 3층 추천 출발점을 확정한다.
2. 고급 설정의 **모의 직진 8걸음 + 우회전 8걸음**을 누른다. 모의 값은 시간 간격을 두고 재생하며, 파란 점·선·`지도 좌표 변화`가 여러 차례 갱신되는지 확인한다. 모의 결과는 실제 센서 결과와 구분해 기록한다.
3. 실제 휴대폰에서 **추천점에서 센서 켜기**를 누르고 권한을 허용한 뒤 5m 직선, 약 90° 회전, 제자리 폰 회전을 각각 시험한다. iPhone Safari는 버튼 클릭 중 센서 권한을 요청하며 Android Chrome도 HTTPS와 기기 센서 지원이 필요하다.
4. 실제 거리·회전값과 감지 걸음·추정 거리·방향·좌표 변화를 비교하고 JSON 기록을 내려받는다. 센서 값이나 좌표가 계속 바뀌는데 점만 멈춘다면 표시 문제, 걸음만 바뀌고 좌표가 고정되면 방향 또는 좌표 계산 문제로 분리해 조사한다.

자동 테스트는 실제 3층 그래프에 모의 센서 값을 넣고 중간·최종 좌표와 SVG 점의 이동을 확인한다. 이는 브라우저 DOM 계산의 검증이며, iPhone·Android의 실제 센서 정확도와 현장 통로 매칭 성능을 입증하지는 않는다.
